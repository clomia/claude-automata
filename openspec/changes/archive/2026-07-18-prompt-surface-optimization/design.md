## Context

프롬프트 표면은 자유 산문이 아니라 시스템의 정책층이다. 상당수 문장이 훅 동작·정본 결정과 짝지어진 계약이고, 일부는 테스트가 문면을 단정한다. 최적화는 문장 취향이 아니라 수신자의 총 맥락(동거 맥락)에 대한 전역 추론이어야 한다.

## Goals / Non-Goals

**Goals:**
- 표면별 ROI(정보량/글자수) 최대화 — 삭제가 default, 추가는 전역 정당화 필요.
- deterministic 로직의 코드 이관.
- 도메인 간 용어·형식 일관.

**Non-Goals:**
- behavior 요구사항 변경(트리거 조건, 게이트 순서, 종료 판정 등은 불변).
- 계약 행의 의미 개정(짝 정본의 개정은 이 change 범위 밖).
- 사람 대상 문서(README 한·영)의 개정.

## Decisions

- open의 preflight·분기(산문 로직)를 `open-tx` 엔트리포인트로 코드 이관한다. fetch 실패는
  fail-closed(exit 1)다 — 무결성 경계는 낡은 base 위에서 열리면 안 된다. 기존 열림 경로에
  없던 신규 결정이며, stderr 지시 후 재실행이 수리 경로다.
- 최적화는 도메인 5 병렬 워크플로우로: census(표면 전수) → 수신자 시뮬레이션·제안 → 적대 반박 → 통합 → 적용 → 재검증. refine:docs의 교차검증 구조를 차용한다 — 제안은 반박을 생존해야만 적용된다.
- 전역 삭제 판정식: 어떤 행이 삭제 가능한 것은 그 정보가 수신자의 동거 맥락에서 재구성될 때뿐이다. 판정 주체는 최적화 작업자가 아니라 시뮬레이션된 수신자다.
- 지불 빈도를 우선순위 축으로: 매 라운드(advisor instruction) > 매 spawn(synod 임무·스키마 description) > 재주입(launch) > 세션 1회(open/close) > 조건부 로드(docs-surface).
- 공유 표면은 단일 작성자: synod.md는 refine 3 도메인의 제안을 통합자가 병합, docs-surface.md는 tx 원본 수정 후 refine 사본 재복사(byte-identical 유지).
- 계약 행 목록을 브리프에 사전 명시해 반박 단계가 기계적으로 대조한다.
- (실측) delta 없는 change는 openspec validate가 항상 ERROR를 내지만 archive에서는 non-blocking
  경고로 강등되어 `--skip-specs` 아카이브가 성공하고, 아카이브 후 `validate --all --strict`는
  green이다. 이 클래스의 관문은 태스크 완료 + archive + 사후 CI이며, 이를 모르는 tx:plan의
  "validate green" 문면은 이번 change의 수리 대상이다.

- 무결성 패스는 refine:integrity의 판단 axiom을 차용한다: 모든 도달 가능한 상태는 유효하거나
  명시적으로 정의된 에러여야 하고, 방어 코드의 남발은 무결성이 아니라 복잡성이다. 근거는
  사용자 첨부 공식 문서 코퍼스(축자 보존본)와 실측이며, 추측성 위해는 반박 단계가 기각한다.
  이 패스가 만드는 프롬프트 수정은 최적화 기준(irreducible)으로 전건 재검수한다 — 두 워크플로우가
  서로의 회귀를 만들지 않아야 트랜잭션이 닫힌다.

## Risks / Trade-offs

- [삭제가 암묵 지시를 파괴] → 반박 단계가 수신자 총 맥락 기준으로 재구성 가능성을 검증, 실패 시 제안 기각.
- [테스트가 구 문면을 단정해 red] → 적용 단계가 표면과 테스트를 동일 커밋에서 동기화.
- [정본이 표면 문구를 인용] → 통합 단계가 git grep으로 인용 지점을 스캔해 동반 개정.
- [최적화 문구 자체가 slop 추가] → 반박 단계의 명시 공격 축.
