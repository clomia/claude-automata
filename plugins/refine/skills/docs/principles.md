# 문서 원칙

> **실행시킬 수 없는 텍스트는 모두 문서다. 적을수록 오래 정확하다.**

## Ground Truth

코드만이 실행되고, 실행되는 것만이 진실이다.  
마크다운, 문서 시스템(openspec 등), 주석·docstring, 설정의 설명 텍스트는 코드에 대한 주장(claim)의 집합이다.  
**문서의 모든 주장은 코드로 검증 가능해야 한다.**  
틀린 주장은 주장이 없는 것보다 해롭다 — 독자는 문서를 의심하지 않는다.

의도와 구현이 충돌하면 문서를 코드에 정합시킨다.  
단, 충돌이 코드의 결함을 드러내면 그것은 수정 대상이 아니라 보고 대상이다.

## Irreducible

같은 정보가 두 곳에 있으면 반드시 한 곳은 낡는다.  
모든 표현은 중복과 불일치 없이 irreducible해야 한다.

- 중복 서술은 한 곳으로 수렴시키고 나머지는 삭제하거나 참조로 바꾼다.
- 코드가 이미 설명하는 내용을 재언하는 주석은 부채다. 삭제가 곧 수정이다.
- 대상이 사라진 문서(죽은 문서)는 삭제한다.

## 최소 문서

문서는 코드가 설명할 수 없는 것 — 의도·제약·이유 — 만 담는다.  
정합의 방향은 언제나 삭제·축약이 우선이다. 새 텍스트 추가는 최후의 수단이다.
