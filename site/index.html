PLUGIN SUITE FOR CLAUDE CODE · FOUR MODULES · ONE MEMORY SYSTEM

An autonomous agent environment,
modeled on human memory

claude‑automata turns Claude Code into a running system rather than a conversation: a loop that holds the initiative around the clock, anchored to intent you write once; a consolidation gate that verifies what may be remembered; and a long‑term memory made entirely of git‑tracked text.

01PREMISE

The loop owns the initiative

Every time the agent tries to stop, a hook blocks the stop and summons an independent advisor that inspects the round with a clean context and surfaces what the main agent missed. There is no round cap — the loop ends when the advisor judges there is nothing left to advise. Work spans days and survives repeated auto‑compaction: the anchor — your intent, written once — is preserved outside the transcript and re‑injected whenever context is rebuilt.

The user is one event type

A typed prompt, a schedule firing, CI finishing, a task notification — all of them are just events arriving at an anchored loop. None of them stops it. You can steer mid‑flight or ask a read‑only docent session what is going on; the loop absorbs the input and resumes at the next stop. By design, every contribution to the repository is made by Claude Code agents — humans provide intent and observe.

Memory passes through one gate

Nothing becomes long‑term memory except through a transaction: planned intent, an independent verifier, CI, then a squash merge. Everything else — loop state, dead ends, trial and error — dies with the loop. Forgetting is a feature, not a failure: what remains is exactly what was verified.

02THE MEMORY SYSTEM

The circuit above is not a metaphor bolted on afterwards — it is the design canon. Each stage is one plugin's domain, and the whole of it is specified in MEMORY.md KO.

  1. WORKING MEMORY

    The ploop workspace: the anchor, loop‑local state, candidate facts and terms awaiting promotion. It is untracked and lossy on purpose — rounds are discarded, and an advisor loop keeps the work anchored instead of drifting.

  2. CONSOLIDATION

    A tx transaction is the only way anything is written into memory: change artifacts record the intent, an independent verifier checks the implementation against it, CI must be green, and the result lands as a single squash merge.

  3. LONG‑TERM MEMORY

    All of the repository's git‑tracked, non‑executable text: requirement specs (semantic), archived changes (episodic), design canons and research records, operating rules, glossary terms (lexical), skills (procedural). Recall is grep — names are chosen to be found.

  4. RE‑GROUNDING

    Memory decays while it sits. The refine workflows re‑verify documented claims against the code, prune what can no longer be verified, and converge duplicates — and their fixes pass through the same gate as everything else.

03MODULES

ploop

ADVISOR LOOP

An autonomous loop for long, multi‑day work. Write an anchor — a mission with completion criteria, or an open‑ended purpose — and launch; on every stop an independent advisor surfaces overlooked regions until nothing remains. It runs on the official nested‑subagent path only, creating no separate sessions, so it is safe on subscription plans. A read‑only docent answers your questions from the loop's records without touching it.

CANON — plugins/ploop/ARCHITECTURE.md KO

tx

TRANSACTION GATE

A Git workflow that treats change as a transaction — an integrity boundary, not a unit of work. /tx:open cuts a branch off the base; plan, apply and an independent verify stage drive the change; /tx:close squash‑merges it back only when verification, a docs gate and CI all pass. Guard hooks keep the base branch protected in between.

CANON — plugins/tx/README.md

refine

MAINTENANCE WORKFLOWS

Heavyweight multi‑agent workflows (hours per run) that eliminate accumulated debt: code architecture, documentation truth, and integrity boundaries. Regions are analyzed in parallel, findings settle through cross‑examination into consensus, and only the highest‑ROI plans are executed. In the docs pass, code is never modified — code defects are reported, not fixed.

CANON — plugins/refine KO

version‑up‑alert

UPDATE NOTICE

When a newer release of any installed claude‑automata plugin ships, one line appears at session start naming every plugin that is behind. Alert‑only — it never swaps a plugin under a running session; you choose when to update. Every other plugin installs it as a dependency, so there is nothing to install.

SOURCE — plugins/version‑up‑alert

04GETTING STARTED

One command converges a repository to the environment's prerequisites. Requires Claude Code and uv on a POSIX system (macOS / Linux / WSL). Run it at your project root: 

uvx claude-automata init

WHAT INIT ACTUALLY WRITES

Full disclosure — this environment assumes unattended operation, and init configures Claude Code accordingly. With bypassPermissions the agent edits files and runs commands without asking first; adopt this in a repository where you accept that mode. Review the diff before you commit it.

Settings that init merge-writes into .claude/settings.json
permissions.defaultMode"bypassPermissions" — no approval prompts
model"opus[1m]" — pinned, 1M‑token context
alwaysThinkingEnabledtrue
autoCompactEnabledtrue — long loops depend on it
autoMemoryEnabledfalse — memory belongs to the repo, not the harness
marketplace + pluginsregisters clomia/claude-automata, enables all four plugins
external CLIsinstalls missing gh, Node.js ≥ 20, repomix into ~/.local — no sudo, present tools skipped, gh auth login stays yours

Merge‑write: unrelated keys in .claude/settings.json are preserved, and re‑running is idempotent.

THEN LAUNCH A LOOP

# in one session — write the anchor with the interview skill
/ploop:define-mission

# in a fresh session — hand the anchor text to the loop
/ploop:launch [anchor text]
