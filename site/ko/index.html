인간 기억 구조를 사상한 CLAUDE CODE AGENT 환경

24/7 완전 자율주행.
모두 위임하고 쉬세요.

claude‑automata는 Claude Code를 대화가 아니라 돌아가는 system으로 바꿉니다. 의도를 한 번 적어두면 loop가 24시간 주도권을 쥐고, advisor는 일이 남아 있는 한 끝내지 못하게 하며, 하나의 gate가 무엇을 기억할지 정합니다. 장기기억은 repository의 git 추적 text 그 자체입니다 — 검증되지 않은 것은 loop와 함께 사라집니다, 의도적으로.

01"끝났다"는 선언도 감사받습니다

agent는 끝났다고 믿는 순간 turn을 끝냅니다. 여기서는 그 정지 자체가 event입니다: hook이 정지를 막고 clean context의 독립 advisor를 소집합니다 — loop의 메타인지입니다. "끝났다" 뒤에도 무언가가 계속 묻습니다: 정말 끝났는가?

agent임무 완료. 종료합니다.
hook정지 차단 — advisor를 소집합니다.
advisor아직입니다. mobile layout은 측정된 적이 없습니다. 출처 없는 주장이 둘 있습니다. 승격 대기열에 사실이 남아 있습니다.
agent…재개합니다.
⟲ 여섯 round 뒤
advisor더 조언할 것이 없습니다. turn을 끝냅니다.

연출된 대화입니다 — 기제는 실제입니다: 정지를 차단하는 hook, clean context의 advisor, 그리고 loop를 끝낼 권한은 advisor에게만 있다는 규칙. round 상한은 없습니다 — 종료는 counter가 아니라 판단입니다.

02작동 원리

의도는 무엇에도 살아남습니다

anchor — 한 번 적어둔 당신의 의도 — 는 transcript 밖에 보존되고 context가 재구성될 때마다 다시 주입됩니다. 그래서 작업은 며칠을 넘기고 거듭되는 auto‑compaction에서도 살아남습니다. advisor는 매 round anchor를 새로 읽습니다 — loop는 마지막으로 한 말이 아니라 anchor에 정박합니다.

사용자는 event type 중 하나입니다

타이핑한 prompt, schedule 발동, CI 완료, task notification — 전부 정박된 loop에 도착하는 event일 뿐입니다. 어느 것도 loop를 멈추지 않습니다. 도중에 지시를 넣거나 read‑only docent session에 상황을 물어볼 수 있습니다 — loop는 입력을 흡수하고 다음 정지에서 재개됩니다. 설계상 이 repository의 모든 기여는 Claude Code agent가 작성합니다 — 인간은 의도를 주고 관찰합니다.

기억은 하나의 gate만 통과합니다

transaction을 통하지 않고는 어떤 것도 장기기억이 되지 못합니다: 계획된 의도, 독립 verifier, CI, 그리고 squash merge. 그 밖의 모든 것 — loop 상태, 막다른 길, 시행착오 — 은 loop와 함께 사라집니다. 망각은 결함이 아니라 기능입니다: 남는 것은 오직 검증된 것뿐입니다.

03기억 SYSTEM

위의 회로는 나중에 붙인 은유가 아니라 설계 그 자체입니다: 세 plugin이 단계를 구동하고, 저장소는 repository의 git 추적 text입니다. database도 vector index도 없습니다 — 검증된 merge가 하나씩 쌓여 만들어지는 파일들입니다.

  1. WORKING MEMORY

    ploop의 작업 공간: anchor, loop-local 상태, 승격을 기다리는 사실·용어 후보들. 의도적으로 미추적이고 lossy합니다 — round는 폐기되고, advisor loop가 표류 대신 정박을 지킵니다.

  2. CONSOLIDATION

    tx transaction은 기억에 무언가를 쓰는 유일한 방법입니다: change artifact가 의도를 기록하고, 독립 verifier가 구현을 그 의도와 대조하고, CI가 green이어야 하며, 결과는 하나의 squash merge로 안착합니다.

  3. LONG‑TERM MEMORY

    repository의 git 추적되는 비실행 text 전부: 요구사항 spec(의미기억), archive된 change(일화기억), 설계 정본과 조사 기록, 운영 규칙, 용어 (어휘기억), skill(절차기억). 회상은 grep입니다 — 이름은 grep에 걸리도록 짓습니다.

  4. RE‑GROUNDING

    기억은 놓아두는 동안 부패합니다. refine workflow가 문서의 주장을 코드와 재대조하고, 더는 검증할 수 없는 것을 지우고, 중복을 수렴시킵니다 — 그 수정 역시 다른 모든 것과 같은 gate를 통과합니다.

04MODULES

ploop

ADVISOR LOOP

며칠짜리 장기 작업을 위한 자율 loop입니다. anchor — 완료 조건이 있는 mission, 또는 끝이 없는 purpose — 를 적어 launch하면, 매 정지마다 독립 advisor가 미고려 영역을 표면화하고, 남은 것이 없어질 때까지 계속됩니다. 정식 nested‑subagent 경로만 사용하고 별도 session을 만들지 않아 구독 요금제에서도 안전하게 쓸 수 있습니다 — 여기서 '안전'은 동작 기제 이야기지 비용이 들지 않는다는 뜻이 아닙니다: loop는 요금제 quota를 공유하며, 며칠짜리 실행은 quota를 그만큼 소모합니다. read‑only docent가 loop를 건드리지 않고 기록에서 질문에 답합니다.

tx

TRANSACTION GATE

변경을 transaction — 작업 단위가 아니라 무결성 경계 — 으로 다루는 Git workflow입니다. /tx:open이 base에서 branch를 따고, tx:plan → tx:apply → tx:verify가 독립 verify 단계와 함께 변경을 이끌며, /tx:close는 verification·docs gate·CI가 전부 통과했을 때만 squash merge합니다. 그동안 base branch는 guard hook들이 지킵니다.

refine

MAINTENANCE WORKFLOWS

쌓인 부채를 없애는 heavyweight multi‑agent workflow(한 번에 3–12시간)입니다: 코드 architecture, 문서의 참, 무결성 경계. 영역을 나눠 병렬 분석하고, 발견은 교차검증 회의에서 합의로 걸러지며, 최고 ROI 계획만 실행됩니다. docs pass는 코드를 절대 수정하지 않습니다 — 결함은 보고됩니다. /refine:code · /refine:docs · /refine:integrity로 호출하고, 선택 인자로 영역을 좁힙니다.

05시작하기

command 하나면 repository가 이 환경을 돌릴 준비를 마칩니다. Claude Code와 uv가 필요하고, POSIX(macOS / Linux / WSL)에서 동작합니다. project root에서 실행하세요: 

uvx claude-automata init

INIT이 실제로 기록하는 것

전부 공개합니다 — 이 환경은 무인 운용을 전제하며 init은 Claude Code를 그에 맞게 설정합니다. bypassPermissions에서는 agent가 묻지 않고 이 machine에서 shell command를 실행합니다 — 신뢰의 범위는 repo가 아니라 host입니다. 그 방식을 수용할 machine에서 도입하고, commit 전에 diff를 확인하세요.

init이 .claude/settings.json에 merge-write하는 설정
permissions.defaultMode"bypassPermissions" — 승인 prompt 없음
model"opus[1m]" — model 고정, 1M‑token context
alwaysThinkingEnabledtrue
autoCompactEnabledtrue — 장기 loop가 여기 의존합니다
autoMemoryEnabledfalse — 기억은 harness가 아니라 repo의 것
marketplace + pluginsclomia/claude-automata 등록, plugin 활성화
external CLIs없는 gh·Node.js ≥ 20·repomix를 ~/.local에 설치 — sudo 불필요, 있으면 건너뜀, gh auth login은 당신 몫

merge‑write입니다: .claude/settings.json의 무관한 key는 보존되고, 재실행은 idempotent합니다.

그리고 LOOP를 돌리세요

# 한 session에서 — interview skill로 anchor를 작성
/ploop:define-mission

# 새 session에서 — anchor text를 loop에 전달
/ploop:launch [anchor text]
# loop 조작
/ploop:off      # 일시정지 — loop는 다음 정지에서 멈춥니다
/ploop:on       # 재개 — ESC·API error·session limit로 멈춘 loop도 깨웁니다
/ploop:docent   # 별도 session에서 질문 — read-only, loop를 건드리지 않습니다

claude‑automata는 claude‑automata로 개발됩니다: 이 repository의 모든 기여는 이 page가 설명하는 loop를 돌리는 Claude Code agent가 작성했습니다. 재귀적 자기개선이 실제로 돌아가고 있습니다.
