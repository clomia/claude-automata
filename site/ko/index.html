인간 기억 구조를 사상한 CLAUDE CODE AGENT 환경

24/7 완전 자율주행.
모두 위임하고 쉬세요.

Claude Code는 대화가 끝나면 멈춥니다. claude‑automata는 Claude Code를 계속 돌립니다: 의도를 한 번 적어두면 loop가 24시간 주도권을 쥡니다. advisor는 일이 남아 있는 한 끝내지 못하게 하고, 하나의 gate가 무엇을 기억할지 정합니다.

01"끝났다"는 선언도 감사받습니다

agent는 끝났다고 믿는 순간 turn을 끝냅니다. 여기서는 그 정지 자체가 event입니다: hook이 정지를 막고 clean context의 독립 advisor, 곧 loop의 메타인지를 소집합니다. "끝났다" 뒤에도 무언가가 계속 묻습니다: 정말 끝났는가?

agent임무 완료. 종료합니다.
hook정지 차단. advisor를 소집합니다.
advisor아직입니다. mobile layout은 측정된 적이 없습니다. 출처 없는 주장이 둘 있습니다. 승격 대기열에 사실이 남아 있습니다.
agent…재개합니다.
⟲ 여섯 round 뒤
advisor더 조언할 것이 없습니다. turn을 끝냅니다.

연출된 대화입니다. 기제는 실제입니다: hook이 정지를 차단하고, loop를 끝낼 권한은 advisor에게만 있습니다.

끝났다는 말로는 끝나지 않습니다. 정말 끝나야 끝납니다.

02작동 원리

의도는 무엇에도 살아남습니다

anchor(한 번 적어둔 당신의 의도)는 transcript 밖에 보존되고 context가 재구성될 때마다 다시 주입됩니다. 그래서 작업은 며칠을 넘기고 auto‑compaction에서도 살아남습니다. advisor는 매 round anchor를 새로 읽습니다. loop는 마지막으로 한 말이 아니라 anchor에 정박합니다.

사용자는 event type 중 하나입니다

타이핑한 prompt, schedule 발동, CI 완료, task notification: 전부 정박된 loop에 도착하는 event일 뿐입니다. 어느 것도 loop를 멈추지 않습니다. 도중에 지시를 넣거나 read‑only docent session에 상황을 물어볼 수 있습니다. loop는 입력을 흡수하고 다음 정지에서 재개됩니다. 당신은 의도를 주고 관찰합니다.

기억은 하나의 gate만 통과합니다

검증된 transaction을 통하지 않고는 어떤 것도 장기기억이 되지 못합니다. 그 밖의 모든 것(loop 상태, 막다른 길, 시행착오)은 loop와 함께 사라집니다. 망각은 설계입니다: 남는 것은 오직 검증된 것뿐입니다.

03기억 SYSTEM

위의 회로는 나중에 붙인 은유가 아니라 설계 그 자체입니다: 세 plugin이 단계를 구동합니다. database도 vector index도 없습니다. 검증된 merge가 하나씩 쌓여 만들어지는 파일들입니다.

  1. WORKING MEMORY

    ploop의 작업 공간: anchor, loop-local 상태, 승격을 기다리는 사실·용어 후보들. 의도적으로 미추적이고 lossy합니다. round는 폐기됩니다.

  2. CONSOLIDATION

    tx transaction은 기억에 무언가를 쓰는 유일한 방법입니다: change artifact가 의도를 기록하고, 독립 verifier가 구현을 그 의도와 대조하고, CI가 green이어야 하며, 결과는 하나의 squash merge로 안착합니다.

  3. LONG‑TERM MEMORY

    repository의 git 추적되는 비실행 text 전부: 요구사항 spec(의미기억), archive된 change(일화기억), 설계 정본과 조사 기록, 운영 규칙, 용어 (어휘기억), skill(절차기억). 회상은 grep입니다. 이름은 grep에 걸리도록 짓습니다.

  4. RE‑GROUNDING

    기억은 놓아두는 동안 부패합니다. refine workflow가 문서의 주장을 코드와 재대조하고, 더는 검증할 수 없는 것을 지우고, 중복을 수렴시킵니다. 그 수정 역시 다른 모든 것과 같은 gate를 통과합니다.

04MODULES

ploop

ADVISOR LOOP

며칠을 넘기는 작업을 위한 자율 loop입니다. anchor(끝이 있는 mission, 또는 끝이 없는 purpose)를 작성해 launch하면 그다음은 loop의 몫입니다. 멈출 때마다 독립 advisor가 놓친 것을 표면화하고, 남은 것이 없어질 때까지 계속됩니다.

tx

TRANSACTION GATE

변경을 transaction(무결성 경계)으로 다루는 Git workflow입니다. loop의 agent들이 알아서 사용합니다: 모든 변경은 검증과 CI를 통과한 하나의 squash merge로 안착하고, 그동안 base branch는 guard hook이 지킵니다. 당신은 진행 중인 작업이 아니라 merge된 결과를 봅니다.

refine

MAINTENANCE WORKFLOWS

낡아가는 repository를 참으로 되돌리는 workflow 3개입니다. /refine:code는 코드 architecture를 재작업하고, /refine:docs는 문서를 코드와 재대조하고, /refine:integrity는 동작 무결성을 확보합니다. 필요할 때 영역을 지정해 실행하세요. 각각 수 시간짜리 multi‑agent pass입니다.

05시작하기

git repository에서 아래 command를 실행하면 셋업이 완료됩니다.

REQUIRES · Claude Code · uv · POSIX (macOS / Linux / WSL)

uvx claude-automata init

INIT이 실제로 기록하는 것

전부 공개합니다. 이 환경은 무인 운용을 전제하며 init은 Claude Code를 그에 맞게 설정합니다. bypassPermissions에서는 agent가 묻지 않고 이 machine에서 shell command를 실행합니다. 신뢰의 범위는 repo가 아니라 host입니다. 그 방식을 수용할 machine에서 도입하고, commit 전에 diff를 확인하세요.

init이 .claude/settings.json에 merge-write하는 설정
permissions.defaultMode"bypassPermissions" (승인 prompt 없음)
model"opus[1m]" (model 고정, 1M‑token context)
alwaysThinkingEnabledtrue
autoCompactEnabledtrue (장기 loop가 여기 의존합니다)
autoMemoryEnabledfalse (기억은 harness가 아니라 repo의 것)
marketplace + pluginsclomia/claude-automata 등록, plugin 활성화
external CLIs없는 gh·Node.js ≥ 20·repomix를 ~/.local에 설치 (sudo 불필요, 있으면 건너뜀, gh auth login은 당신 몫)

merge‑write입니다: .claude/settings.json의 무관한 key는 보존되고, 재실행은 idempotent합니다.

06LOOP를 돌리세요

운용 표면은 이것이 전부입니다: anchor를 쓰고, launch하고, 원할 때만 개입합니다.

1 · ANCHOR 작성

# interview가 당신의 의도를 받아 적습니다
/ploop:define-mission   # 끝이 있는 mission
/ploop:define-purpose   # 끝이 없는 purpose

2 · LAUNCH

# 새 session에서: anchor를 loop에 전달
/ploop:launch [anchor text]

3 · 조작

/ploop:off      # 일시정지: loop는 다음 정지에서 멈춥니다
/ploop:on       # 재개: ESC·API error·session limit로 멈춘 loop도 깨웁니다
/ploop:docent   # 반드시 별도 session에서 실행(같은 directory): read-only, loop를 건드리지 않습니다

4 · REPOSITORY 정비

# mission 사이에: 수 시간짜리 정비 pass
/refine:code       # 코드 architecture 재작업
/refine:docs       # 문서를 코드와 재대조
/refine:integrity  # 동작 무결성 확보

claude‑automata는 claude‑automata로 개발됩니다: 이 repository의 모든 기여는 이 page가 설명하는 loop를 돌리는 Claude Code agent가 작성했습니다. 재귀적 자기개선이 실제로 돌아가고 있습니다.
